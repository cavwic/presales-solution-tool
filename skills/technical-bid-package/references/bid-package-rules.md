# Technical bid package rules

## Response matrix as the control record

The matrix controls the technical volume. Update it when requirements, amendments, clarification answers, section assignments, evidence, owners, responses, deviations, or review states change.

Formal response wording must state what is provided, how it is implemented, any condition or boundary, where it is described, and how it will be verified. Do not use generic claims such as "fully satisfies" as a substitute for evidence.

## Evidence hierarchy

Prefer current approved materials in this order when available:

1. Contractual product specification or approved SOW.
2. Current product manual and official technical specification.
3. Approved architecture, interface, deployment, test, or certificate file.
4. Approved historical solution that still matches the current product version.
5. Analyst interpretation, clearly marked for review.

An older successful proposal is not proof that the current product still has the same function, parameter, certificate, interface, or service boundary.

## Deviation

- Positive deviation: evidence establishes a measurable result better than the stated requirement under matching conditions.
- No deviation: evidence establishes the exact requirement without hidden conditions.
- Negative deviation: the requirement is not met.
- Pending: evidence or review is incomplete.

Conditional and custom responses normally remain pending or negative until the procuring party accepts the condition. Do not manipulate deviation wording to hide product boundaries.

## Package checks

Check every required document, attachment, certificate, drawing, signature/stamp instruction, file format, naming rule, page rule, medium, deadline, and submission channel. The Skill may record these instructions but cannot perform submission or legal approval.
