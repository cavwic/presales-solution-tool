# 发行与原位更新

## 运行目录与数据

源码项目的固定启动入口、运行包和项目资料库分开保存：

```text
售前解决方案工具.exe
项目资料库/
  历史项目索引.json
  历史项目索引.csv
  资料库说明.txt
  <项目名称>--<稳定标识>/
    项目档案.json
    项目说明.txt
    workspace.json
    projects/<项目ID>/project.json
    0_项目客户方资料/
    1_售前准备/
    2_招标要求/
    3_技术标组包/
    4_中标交底/
    5_输出文件/
release/
  售前解决方案工具-win-x64/
    售前解决方案工具.exe
    resources/
    使用说明.txt
  售前解决方案工具-V<版本号>-win-x64.zip
```

根启动器按相对路径打开当前运行版，桌面和开始菜单快捷方式绑定根启动器。GitHub 便携包包含完整运行目录，解压后直接打开其中的 EXE；便携版的“项目资料库”位于该 EXE 旁。请使用可写目录，不要直接在 ZIP 内运行。

本机便携包文件名使用中文；GitHub V1.8.0 发行资产使用 `Presales-Solution-Tool-V1.8.0-win-x64.zip`，包内 EXE 仍名为“售前解决方案工具.exe”。发布页的 `SHA256SUMS.txt` 按公开资产名称提供校验值。

项目资料库保存项目记录、资料、模板和生成文件，不包含在发行 ZIP 中；应用配置及缓存仍位于 `%APPDATA%/CavwicBidWorkbench`。原有外部项目继续保留其目录绑定，引用文件另行复制到资料库；从历史载入的项目使用资料库中的独立目录。

手动查找可先打开“历史项目索引.csv”，再进入项目文件夹。目录名称在首次保存时固定，后续改名以索引和“项目说明.txt”为准。请勿手改“历史项目索引.json”或“项目档案.json”。

`release/`、根 EXE、“项目资料库”、本机配置及保留快照不进入源码提交。GitHub 发行资产与本机运行数据分别管理。

## 便携版更新与旧项目收录

1. 退出旧程序，备份“项目资料库”和仍在使用的外部项目目录；需要保留配置时，另备份 `%APPDATA%/CavwicBidWorkbench`。
2. 将新便携包完整解压到独立目录，保留配套文件。不要覆盖仍在运行的 EXE 或随意混用不同版本的运行文件。
3. 首次打开新版前，将完整的原资料库复制到新版 EXE 旁的空位置。若新版已保存项目，不要合并或覆盖索引；应启动新版，通过“历史项目 → 收录已有项目”逐个添加旧目录。收录入口选择的是包含 `workspace.json` 和 `projects/` 的项目目录，而不是整个资料库根目录。

收录旧目录会复制项目引用文件，不移动或删除原件；已有项目标识会跳过，不覆盖历史记录。若从“项目设置”导入 ZIP，而相同项目已在资料库中，则建立独立“导入副本”。已删除或从未保存的文件无法由历史功能恢复，缺失引用会标注。

“已投递”由用户手动标记，不会执行采购平台提交，也不会根据生成文件或批准动作自动推定。

## 源码项目原位更新

在项目根目录运行：

```powershell
node scripts/update-desktop.cjs
```

更新工具先准备候选版本，在独立 profile 中执行安装检查。候选通过后，正常关闭当前工具，将原运行目录和启动器暂存为本次更新的恢复副本，再放入新版本。正式路径复验及 ZIP 校验通过后，删除临时恢复副本和旧发行包。

更新失败时会尝试恢复原运行版。恢复副本只用于本次事务恢复，不作为长期历史版本。工具根目录的“项目资料库”、外部项目目录和 `%APPDATA%/CavwicBidWorkbench` 均不作为构建或更新输出目录。

如需手工打包，见 [开发文档](development.md)。不要将新运行文件直接复制进仍在使用的旧运行目录。

## 更新中断后恢复

断电或强制退出可能留下 `release/.update.lock` 及临时恢复副本。锁不会自动按时间失效，先完成检查再重新更新：

1. 确认上一次更新进程已经退出。
2. 检查当前运行目录，以及 `release/.previous`、`.previous-launcher.exe`、`.previous-package.zip` 等已有副本；按实际状态恢复配套的稳定运行目录、根启动器和 ZIP。保留尚未确认用途的恢复文件。
3. 人工完成恢复并核实稳定版可用后，才移除 `release/.update.lock`，再运行更新入口。

失败恢复尚未完成时，应先处理现存副本和锁，不要直接重复升级。

## 版本留存

常规原位更新只保留当前稳定运行目录和对应 ZIP。源码、变更记录、项目资料和配置不属于发行副本清理目标。

维护者本机按专项要求另行保留改版前的原版界面及独立数据快照，位于被 Git 忽略的 `preserved/` 和原版运行目录，不随公开便携包提供，也不自动同步新版后续编辑。不要将这项本机留存理解为公共下载包附带多个版本。

## 移动与备份

迁移源码安装版时，连同根启动器、`release/` 和“项目资料库”一起移动。迁移便携版时，保留 EXE 所在完整运行目录及旁边的资料库。应用配置位于上述 AppData 目录，外部项目按各自位置单独备份。

源码项目迁移后，可在新位置运行：

```powershell
./scripts/rebind-shortcuts.ps1
```

该脚本重新绑定桌面及开始菜单入口，不创建登录或开机启动项。仅存在旧网页浏览器缓存中的内容不会自动迁移到桌面版。

业务文件的 ZIP 交付包与完整项目备份用途不同，备份范围见 [离线使用说明](使用说明.txt)。
