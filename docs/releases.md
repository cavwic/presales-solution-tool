# 发行与原位更新

## 运行目录

成功更新后，本机源码项目保留固定启动入口、当前运行目录及对应便携包：

```text
售前解决方案工具.exe
release/
  售前解决方案工具-win-x64/
    售前解决方案工具.exe
    resources/
    使用说明.txt
  售前解决方案工具-V<版本号>-win-x64.zip
```

根启动器按相对路径打开当前运行版，桌面和开始菜单快捷方式绑定根启动器。GitHub 便携包则包含完整运行目录，解压后直接打开其中的 EXE。

`release/` 和根 EXE 不进入源码提交。GitHub 发行资产与本机运行目录分别管理。

## 更新

在项目根目录运行：

```powershell
node scripts/update-desktop.cjs
```

更新工具先准备候选版本，在独立 profile 中执行安装检查。候选通过后，正常关闭当前工具，将原运行目录和启动器临时保存为更新事务的恢复副本，再放入新版本。正式路径复验及 ZIP 校验通过后，删除临时恢复副本和旧发行包，只留下当前稳定版本。

更新过程中检测到失败时会尝试恢复原运行版。恢复副本只用于本次更新失败恢复，不作为长期历史版本。用户项目目录和 `%APPDATA%/CavwicBidWorkbench` 不作为构建或更新输出目录。

如需手工打包，见 [开发文档](development.md)。不应将新运行文件直接复制进仍在使用的旧运行目录。

## 更新中断后恢复

断电或强制退出可能留下 `release/.update.lock` 及临时恢复副本。锁不会自动按时间失效，先完成检查再重新更新：

1. 确认上一次更新进程已经退出。
2. 检查当前运行目录，以及 `release/.previous`、`.previous-launcher.exe`、`.previous-package.zip` 等已有副本；按实际状态恢复配套的稳定运行目录、根启动器和 ZIP。保留尚未确认用途的恢复文件。
3. 人工完成恢复并核实稳定版可用后，才移除 `release/.update.lock`，再运行更新入口。

失败恢复尚未完成时，应先处理现存副本和锁，不要直接重复升级。

## 版本留存

本机只保留当前最稳定版本的运行目录和对应 ZIP，不持久保留历史版本或回退包。源码、变更记录、项目资料和配置不属于发行副本清理目标。

## 移动软件

迁移本机源码目录时，连同根启动器和 `release/` 一起移动。迁移后在新位置运行：

```powershell
./scripts/rebind-shortcuts.ps1
```

该脚本重新绑定桌面及开始菜单入口，不创建登录或开机启动项。项目资料另按所选项目目录备份；仅存在旧网页浏览器缓存中的内容不会自动迁移到桌面版。

业务文件的 ZIP 交付包和完整项目备份用途不同，备份范围见 [离线使用说明](使用说明.txt)。
